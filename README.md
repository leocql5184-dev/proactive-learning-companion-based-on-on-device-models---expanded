# 智伴同行 · 本地离线学习伙伴

Windows 电脑端学习原型：在用户授权后记录应用内学习活动，提供分步引导、主动帮助、反馈和可纠正的成长记录。默认使用 **llama.cpp + Qwen3-0.6B GGUF（Q8_0）**，模型推理在本机完成。HarmonyOS 与 MindSpore 代码保留为可选研究和迁移路径。

> 当前为研究原型。已支持题目与审核过的教学策略不能代表任意学科能力；情绪假设和模型分数不等于心理诊断，因果评估不等于已验证教学因果效果。电脑端结果不能表述为手机实测。

## 项目介绍

**基于端侧模型的主动式学习伙伴（Proactive Learning Companion Based on On-Device Models）** 面向持续学习与成长陪伴，探索如何让本地智能系统在保护学习数据、尊重用户自主选择的前提下，理解学习过程，并在合适的时机提供帮助。

项目希望把单次问答延伸为持续的学习支持：既关注知识理解与解题进展，也关注学习方法、用户主动表达的感受、学习习惯及其变化。帮助不意味着不断打断；当学习顺利、证据不足或用户希望独立思考时，保持安静同样是合理的决策。

### 创新背景与出发点

学习支持需要理解一道题之外的过程：学习者是否反复卡在相同概念、是否依赖提示、是否需要调整学习方法，以及一次帮助之后能否继续独立尝试。分散的问答往往难以呈现这些变化，长期积累的学习记录也需要清晰的数据边界和用户控制方式。

作品说明提出，将个人隐私保护、实时状态理解和个性化主动服务结合起来，为长期学习建立连续的支持。项目据此探索三个问题：如何在本机组织学习证据，如何随着新证据更新对学习者的理解，以及如何让主动帮助既有依据又不过度打扰。

### 设计理念

- **本地智能底座**：尽可能在设备上完成推理和数据处理，让学习支持不必依赖持续上传个人学习过程。离线使用是技术方向，具体保护能力仍以实际实现和安全边界为准。
- **从学习过程理解需求**：将任务进展、作答变化、求助和用户自报放在具体情境中解释，而不是只看一次答案对错。停顿可能意味着思考，不能单独作为负面情绪或能力不足的证据。
- **可更新的长期理解**：画像记录阶段性的观察及其依据，允许新证据修正旧判断；不把某次挫折写成永久性格标签，也不把用户锁定在单一能力评价中。
- **适度、可拒绝的主动服务**：通过认知与情感围栏约束提示深度、表达方式和打扰频率。帮助应服务于学习者继续理解和尝试，用户始终可以暂停、推迟或拒绝。
- **以反馈形成闭环**：不仅记录是否展示了建议，也关注建议后的尝试与反馈。缺少观察时保持未知，避免把“发出了帮助”当作“产生了效果”。

### 成长画像关注什么

作品说明关注学科能力、学习方法、情绪状态、行为习惯与长期成长轨迹。项目将这些关注点组织为三个可持续更新的维度：

| 维度 | 关注内容 | 证据与解释边界 |
| --- | --- | --- |
| 知识与能力 | 概念理解、先修知识、错误路径、独立完成情况与理解变化 | 区分独立作答和接受提示后的表现，不以单次正确答案断言已经掌握 |
| 情绪与个体特点 | 用户主动表达的感受、情境中的情绪线索及长期偏好 | 区分自报与系统假设；关于个体特点的判断需要长期证据和用户纠正，不作为心理诊断 |
| 学习态度与习惯 | 求助方式、反复尝试、停顿、休息后恢复、策略使用等过程 | 描述可观察行为及其情境，不把行为直接等同于走神、懒惰或固定人格 |

这些维度是建模方向，并不意味着当前电脑端已经能够完整、可靠地测量全部内容。成长记录应保留证据来源、更新时间与适用范围，让用户能够理解记录为何产生，并参与纠正。

### 核心闭环

1. **授权感知**：在用户明确允许的范围内整理作答、修改、停顿、求助和任务进程，形成可追溯的学习事件。
2. **动态成长画像**：结合知识关系和行为证据，逐步更新对知识掌握、情绪线索与学习习惯的理解，保留来源、不确定性以及纠正和清除入口。
3. **主动介入决策**：综合当前学习处境、历史证据和用户偏好，判断是否需要帮助、何时帮助、采用何种引导。
4. **适度学习支持**：通过分步提示、概念追问、休息建议和成长回顾提供支持；用户可以接受、推迟或拒绝。
5. **反馈更新**：将用户反馈与后续学习结果回写到记录中，调整后续支持；没有结果时保留未知，不默认干预有效。

### 主动支持的典型场景

以下场景用于说明作品理念如何落到交互设计，并非已经完成的长期效果实验：

- **遇到知识卡点**：学习者多次修改仍未取得进展时，先判断信息是否足够，再征询是否需要一起分析概念或下一步，而不是立即给出整题答案。
- **需要调整节奏**：学习者主动表示疲惫或烦躁时，提供拆小任务、短暂休息或继续尝试等选择；不凭停顿时间自行断言其情绪。
- **正在顺利学习**：学习者能够持续独立推进时保持安静，避免为了体现“主动”而不断弹出建议。
- **完成任务并回顾**：结合本次尝试、接受的提示和用户反馈，展示有依据的学习回顾，为下一次相似任务积累可检查的记录。

### 面向长期成长的价值

作品说明的长期愿景，是形成能够随学习经历持续适配的私人学习伙伴：既帮助完成眼前任务，也支持学习方法改进、能力提升和成长规划。面向多学科学习及未来更复杂的任务场景，项目希望把知识引导、情绪支持与任务决策连接起来，减少学习支持中的信息割裂。

这一价值仍需要通过持续使用、用户反馈与独立评估验证。全学科覆盖、全天候陪伴和长期成长成效是产品愿景，不代表后台无条件采集信息，也不代表已取得商业规模或教学效果结论。

### 技术路线与实现边界

本地离线小模型承担受约束的策略选择与证据提取，知识关系、符号核查和认知状态模块提供可检查的依据，授权、勿扰和输出校验共同限制介入行为。设计目标是让支持更贴近学习者的实际处境，同时减少不必要的数据传输和打扰。

当前公开版本以 Windows 电脑端为入口，默认采用 GGUF 推理，支持应用内学习任务、反馈、基础成长记录和可检查的主动介入原型。跨应用桌面感知、语音等多模态输入、全学科覆盖与长期陪伴属于扩展方向，不能视为已完成或已验证的能力。HarmonyOS 与 MindSpore 适配代码继续保留。

本节依据《智伴同行作品说明文档》的“介绍文档”部分整理，仅保留产品理念与技术方向；不收录参赛人员、学校、联系方式或签名信息。原文中的绝对隐私与长期效果表述在此作为设计目标理解，不作为验证结论。

## 快速开始（Windows x64）

1. 从本仓库下载源码 ZIP，解压到可写目录，例如 `C:\zhiban`。桌面端无需 DevEco Studio、Python、npm 依赖或显卡。
2. 安装 [Node.js 22 或更新的受支持版本](https://nodejs.org/en/download)。在终端用 `node --version` 检查。
3. 双击 **准备模型.cmd**。首次需要联网，从官方 GitHub / Hugging Face 下载固定版本引擎和约 639 MB 模型，并验证 SHA-256。网络不可用时查看 [安装与故障排查](docs/INSTALL_DESKTOP.md)。
4. 双击 **打开学伴.cmd**，访问 <http://127.0.0.1:8875>。模型准备期间页面显示未就绪，准备完成后可学习、请求帮助和反馈。
5. 用 **关闭学伴.cmd** 停止服务。只关闭浏览器不会停止后台引擎。

建议至少 8 GB 内存、2 GB 空闲磁盘和支持 AVX2 的 x64 CPU；具体速度取决于硬件。ARM Windows、macOS、Linux 暂未提供安装包或兼容性验收。

已准备好模型和引擎后，启动与推理无需联网。没有云模型备用通道。源码 ZIP 不含模型/运行时；它不是解压即可推理的完整离线安装包。

## 开发与测试

```powershell
npm test
powershell -NoProfile -ExecutionPolicy Bypass -File tools/local-llm/Prepare-Desktop.ps1
npm start
# 另一个终端：实际模型路由与神经证据验收
npm run test:smoke
npm run test:security
```

桌面端仅使用 Node 标准库，无 `npm install` 步骤。`.env.example` 是环境变量说明，不自动加载；双击启动器使用固定端口，`npm start` 可读取当前进程的环境变量。

## 项目结构

| 文件/目录 | 用途 |
| --- | --- |
| `tools/local-llm/desktop/` | 本地 HTTP 服务、网页、符号/认知/介入模块 |
| `tools/local-llm/skills/` | 运行时实际加载的教学围栏 |
| `assets/guidance/` | 数值辅助模型、预处理和特征定义；不含原始学习日志 |
| `tools/local-llm/runtime-manifest.json` | 固定下载地址、引擎版本与模型 SHA-256 |
| `tools/release/` | 测试入口、白名单导出、安全扫描与 ZIP 打包 |
| `tests/` | 桌面回归、真实模型与访问安全检查 |
| `entry/`、`AppScope/` | 保留的 HarmonyOS 接入代码；桌面启动不依赖它们 |
| `tools/model-conversion/` | 保留的 MindSpore 转换/服务源码，非默认工作流 |
| `models/` | 本机模型，权重不进入公开 Git 仓库 |
| `docs/` | 安装、公开发布、安全审计、设计与历史记录 |
| `.github/workflows/desktop.yml` | 桌面回归和可手动触发的完整 GGUF 安装验收 |

## 隐私与安全

服务与引擎仅监听 `127.0.0.1`，拒绝异站来源和 Host 伪造，引擎使用每次启动生成的随机密钥。网页只允许列出的静态文件；不开放模型、磁盘或命令执行接口。

学习记录保存在当前浏览器的 localStorage，聊天保留在本次页面内存中；“清除记录”处理应用记录。同一电脑上的其他进程、浏览器扩展、同一用户账号仍可能访问本地数据。调试日志可能包含推理上下文，勿公开日志或个人数据。详见 [安全政策](SECURITY.md) 与 [本次安全审计](docs/PUBLICATION_AUDIT.md)。
